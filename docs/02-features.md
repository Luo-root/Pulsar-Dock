# 02 · 功能与交互

版本：v0.1 讨论稿｜2026-10-23｜除标明需求外，细节均为设计建议

## 1. 用户只需要理解四个对象

- **项目**：用户想处理的资料及其原始位置。
- **任务**：要完成的目标，可以包含子任务。
- **Agent 环境**：某个 Agent 的隔离工作空间、权限和运行资源。
- **成果**：指定版本的文件、差异、测试结果或审查结论。

同一个任务可以重试，每次运行有独立记录；停止进程不等于删除成果，任务成功不等于改动已应用。

## 3. 桌面信息结构

一共五个主要页面，不让用户先理解架构：

1. **项目与任务**：项目列表、最近任务、新建任务；显示运行中、等你确认、已完成、失败。
2. **任务工作台**：左侧任务与协作者列表，中间 Agent 原生交互区域，右侧权限与事件；底部成果入口。原生事件缺失时只展示已知状态，不推测进度百分比。
3. **连接中心**：模型、Magpie、MCP 卡片；显示已连接、需授权、不兼容、不可用。真实密钥只在可信设置界面输入，不进入聊天记录。
4. **审批与成果**：待处理的权限申请和成果差异；审批说明操作目标、范围、有效期及风险。
5. **设置与诊断**：版本、资源额度、日志导出和环境清理；高级配置默认折叠。

Agent 提供的 HTML、终端控制序列、链接和 Markdown 都是非可信内容。展示区域不能获得桌面管理接口权限。

## 4. 首次使用：三步开始

### 第一步：选择项目和 Agent

用户选目录；Dock 展示导入预览与排除项。默认排除常见密钥文件、凭据目录和不需要的大型产物，但提示“过滤不能识别全部敏感内容”。用户可缩小范围；不能把“排除 .env”当作完整数据防泄漏。

Agent 卡片说明版本与能力。未安装时显示安装来源和所需授权；不在用户不知情时安装系统组件。

### 第二步：连接能力并查看权限

用户选择模型和 MCP 连接，默认权限为：修改独立副本、访问选定模型、使用选定工具、不可直接访问宿主私有目录、不可自行发布。

协作开关以自然语言表达：“允许它创建一个协作者，协作者只能读取指定成果”。展示建议初值：最多同时两个环境、派生一层、单任务 30 分钟；这些是可调整设计参数，不是既有决定。

审批策略允许用户按任务或全局选择三档：

- **安全模式**：Agent 发起的每一次 Dock 能力操作都询问用户，包括重复操作；一个请求的网络重试只对应同一次审批。界面自动刷新和平台内部心跳不算 Agent 操作，紧急停止与撤权不等待 Agent 或额外审批。
- **标准模式**：低风险、已在任务授权摘要内的操作自动放行；跨项目读取、创建协作者、写入外部服务和其他高风险操作询问用户。首版默认使用此模式。
- **自动授权模式**：默认同意 Dock 已声明范围内的操作，适合用户明确选择的低风险任务；超出范围、改变授权对象或触发系统禁止项仍然拒绝，并提示用户。自动授权不等于允许 Agent 修改策略、读取宿主私密目录或执行未声明的外部发布。

模式切换要显示影响范围，并记录是谁、何时、对哪个任务启用了它。高风险动作即使在自动授权模式下也可以被系统策略强制拦截。

### 第三步：输入目标并启动

启动按钮前给出一句权限摘要。后台检查未通过时按钮禁用并提供具体修复步骤。成功后直接进入任务工作台，不要求用户填写容器镜像参数或手改 MCP 配置。

## 5. 核心协作流程

示例目标：“实现功能，并请一个独立 Agent 审查。”

1. 主 Agent 在副本中完成候选修改，通过 Dock 提交成果快照。
2. 主 Agent 调用创建子任务能力，指定模板、目标、成果引用和权限需求。
3. Dock 验证身份、委派范围、并发和额度。权限不足则在可信审批页提出申请；未批准不执行。
4. Dock 从快照创建只读项目输入和独立临时目录，启动审查 Agent。只读指项目输入不可写，不禁止它在临时目录写分析文件。
5. 子 Agent 可询问主 Agent；消息由 Dock 传递并记录来源，不改变接收者权限。
6. 子 Agent 返回结构化完成状态和审查成果引用；主 Agent 收取并汇总。
7. 用户查看实现差异、测试证据和独立审查。是否应用由用户决定。

审查运行测试若需要写项目、下载依赖或执行不可信构建脚本，必须另选获准模板，不能让“只读审查”暗中获得写权限。

### 多 Agent 对抗审查与 Harness 对比

对抗审查先把同一快照交给多个 Agent 独立审查，锁定各自结论后再开放交叉质疑，最后按证据汇总争议，不能靠多数投票判定正确。设置轮数、时间、并发和费用上限，避免无限辩论。

同一工作交给多个 Harness 时，使用相同任务说明、输入快照、权限、Skill/MCP 集合和验收标准，各自写独立副本。对比页展示方案、差异、测试、失败、时长和可获得的用量数据；未知费用标未知。若要比较 Harness 本身，应尽量固定模型与预算；模型无法一致时明确称为“整套配置对比”，不把模型差异归因于 Harness。用户选择成果或交由主 Agent 提议整合，不自动混合多个实现。

## 6. 审批规则

审批卡包含：谁申请、要做什么、目标对象、为什么需要、有效范围、到期时间、拒绝后影响。主按钮使用具体动作，例如“允许本任务读取这份成果”，不用含糊的“继续”。

- 普通任务内已授权操作是否逐次弹窗，由安全模式、标准模式或自动授权模式决定；系统禁止项不受模式影响。
- 发布、推送、删除外部数据等高风险动作默认逐次确认；在自动授权模式下也不能由主 Agent 代表用户批准，除非用户明确为具体范围设置了可审计的授权策略。
- 审批绑定具体参数和对象版本；内容改变重新申请。
- 拒绝或超时返回明确原因，不无限重试弹窗。
- 只控制经过 Dock 的能力；若 Agent 能访问通用外网或远端 shell，不能声称这些动作也被精确审批。因此首版不提供此类绕过路径。

## 7. 停止、失败与成果应用

**停止**：用户停止根任务时，先阻断新请求并撤权，再停止所有后代和进程树；保留已完成快照。外部已提交的动作可能无法撤销，界面须显示“请求已发出，结果待核对”，不可假装全部回滚。

**异常退出**：显示最后已知状态，核对残留环境。没有确认的完成不能变成成功；重开任务默认新运行，只有适配器明确支持才提供续跑。

**应用成果**：显示新增、修改、删除、二进制文件与敏感路径。比较原项目与导入时基线；冲突时停止并让用户选择导出或人工处理。不自动 commit、push、merge、部署，也不自动运行成果中的脚本。

**清理**：删除环境与删除成果分开。未导出成果默认保留并提醒；不默默清空用户原项目。保留期限和磁盘上限在设置页可见。

## 8. 用户体验验收建议

在依赖已准备、连接已有效的条件下，第一次启动不要求编辑 JSON/YAML，不超过三个主要步骤；找一名不熟悉实现的试用者完成任务，记录卡住的位置，不将作者自己的操作速度当易用性证据。

任何安全错误至少提供“什么被拒绝、为什么、可以怎样处理”；不存在仅显示错误码的失败页。键盘可完成审批与停止，运行状态不只靠颜色表达。
