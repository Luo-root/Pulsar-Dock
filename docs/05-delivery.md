# 05 · 三天交付与验收

版本：v0.1 讨论稿｜2026-10-23｜时间盒建议，不是完工保证

## 1. 比赛闭环

**选择项目和 Agent → 无上游密钥的隔离运行 → 主 Agent 创建子环境 → 交换消息并返回固定版本成果 → 用户检查与应用。**

安全第一，易用第二，协作体现差异。实时查看和语音交互只能在此闭环稳定后增加；外部显示方式根据设备生态另行选择，不把 AirPlay 作为默认前提，也不拿普通网页镜像宣称已经完成平台原生投屏。

比赛目标包含主流 Agent 和主流 MCP。三天先完成代表性实现是工程策略，不代表已经满足题目全部兼容范围。交付页必须单独列出完成范围与赛题缺口。

## 2. 三天安排与退出条件

| 时间 | 工作 | 当日必须拿到的证据 | 失败处理 |
|---|---|---|---|
| 第一天前半 | 固定一个 Windows 隔离候选与 Agent/模型组合；验证文件、网络、凭据边界 | 真实模型调用成功；未授权宿主文件不可读；真实上游凭据不进入环境；直连出网被拒 | 不做 UI 扩张；换可行候选。无法建立边界则如实标技术阻塞 |
| 第一天下半 | 创建/停止环境、独立配置、项目快照、模型代理；薄桌面入口 | 一次真实编辑与测试；原目录与全局配置不变；停止无残留 | 缩减装饰和附加能力，不降级成宿主裸跑 |
| 第二天前半 | MCP 受控路径、审批、撤权与兼容检查 | 有凭据工具可用且 Agent 看不到密钥；越权请求被拒；三种审批模式行为可区分 | 明确不兼容传输/认证，不复制凭据兜底 |
| 第二天下半 | task/message/artifact API、一主一子、只读审查 | 主 Agent 实际发起创建；子环境真实运行；消息和成果可追溯 | 保留安全单 Agent 演示，同时明确协作目标未达成 |
| 第三天前半 | 完成成果预览与冲突检测、错误体验、回归和重启测试 | 全链路重跑成功；关键反例测试通过；未通过项有记录 | 冻结新功能，修复阻断缺陷 |
| 第三天下半 | 整理演示、支持矩阵、版本和安装说明 | 在固定版本组合下演示复现；观众可区分能力与限制 | 不临场升级；准备真实录屏仅作故障备份，明确标注录播 |

[建议] 第一天前半结束就做 go/no-go 判断；不能花两天美化界面，最后才发现隔离不可行。

## 3. 首轮最小配置建议

- Windows 为主验证平台；macOS 是后续候选，不能列为首版已支持。
- 一个经过验证的 Agent 是首个完整适配；Codex 可作为首选候选，但由实际探针结果决定。
- 主子可以使用同一种 Agent；跨品牌协作是额外兼容证据，不是创建子环境的前提。
- 连接现有 Magpie 优先；手动兼容服务路径和配套安装按剩余时间推进。
- 同时最多两个环境，最多一层子任务，任务默认 30 分钟；默认不让子任务继续创建后代。
- 无凭据本地 MCP 与至少一条真实的凭据外置 MCP 链路作为基线；其他传输与认证单列缺口。
- 初版副本工作区，不自动合并、不自动发布，不给通用外网访问。

以上都是建议初值，需产品评审和首日验证后锁定。

## 5. 测试组织建议

实现阶段单独规划测试目录：

```text
tests/
  unit/           策略、参数、任务状态、适配配置
  integration/    Gateway、运行时、MCP 与版本组合
  security/       路径逃逸、网络绕过、凭据泄漏、权限派生
  e2e/            UI 启动、子任务、成果应用
  stability/      停止、断进程、重启、清理、重复请求
  performance/    冷热启动、内存、并发与代理延迟
  fixtures/       合成项目与虚拟凭据
```

效果评估：安全项看预期拒绝与允许操作都成立；稳定性看重复运行是否留下孤儿环境或错误状态；性能记录环境和样本，不在首版设计稿虚构毫秒指标。第三天对固定组合连续运行至少三次作为最小稳定性样本，不据此宣称生产级可靠性。

CI 优先覆盖不需要真实账户的策略、适配配置和合成集成测试。需桌面/虚拟化的测试独立标注运行条件，不能因 CI 跳过就记为通过。发现缺陷先开 Issue 再走修复 PR，合并由用户执行。

## 6. 五分钟演示脚本

1. 展示项目原始状态；选 Agent、模型和工具，说明权限摘要。
2. 提交小型实现任务，看到真实终端/事件与文件改动。
3. 主 Agent 请求创建审查环境；展示父子关系、独立环境和成果快照。
4. 展示一次被拒绝的越权请求，以及一次被允许的 MCP 调用；用合成测试证明密钥外置，不展示真实凭据。
5. 展示子 Agent 审查结果，用户查看差异并确认应用。
6. 停止任务，展示环境回收和旧访问凭证失效。

不把伪造进度、静态任务关系图或人工手动启动子进程包装成 Agent 自主调用平台。

## 8. 平台打包与合并门禁

- 最低交付平台为 **Windows 和 macOS**。分别记录架构、包类型、构建工具链、RuntimeBackend 前置条件、实际构建与真机安装/启动结果；Windows 至少 x64，macOS 优先 Apple Silicon，其他架构按明确实测范围声明。
- 未签名/未公证的 macOS 包必须说明系统拦截与安装限制，不假称通过签名；在没有 macOS runner 或真机时报告“未构建/未实测”，不能拿 Windows 或 Web 测试替代。
- 新功能开始前先建或关联现有 Issue，再从独立分支开发并提 PR。每条 PR 合并前，独立子 Agent 必须加载 `deep-code-review` 完成审查；修复后对最新 head 复审，CI 与审查均通过后按当前授权确认合并，禁止绕过失败门禁。
- 桌面 UI 可评估 assistant-ui，但必须先检查其 React/运行时适配与许可证；组件库不改变凭据、权限和非可信网页隔离边界。
- 平台包、安装/运行说明、架构规格与分工、Demo 视频都纳入提交验收。打包阶段不等于获准对外发版或部署。

## 9. 什么可以称为交付完成

文档完成：八份正文与索引存在，定位、权限、功能和验收规则相互一致。

比赛原型完成：P0 闭环真跑通，安全关键项有证据，支持矩阵与缺口如实公开。

生产产品完成：不在三天承诺内；需要更多平台/版本覆盖、升级与恢复验证、长期稳定性和独立安全评估。
