# 04 · 安全与兼容设计

版本：v0.1 讨论稿｜2026-10-23｜以下为要求与验证计划，不是安全认证

## 1. 威胁模型

保护对象：宿主私人文件、上游凭据、原项目、其他任务、服务账户权限与调用额度。

假设 Agent、项目中的脚本、模型返回内容、MCP 工具返回内容、子 Agent 消息都可能恶意或被提示注入。不能依赖它们遵守提示词。

可信边界包括操作系统隔离机制、Dock 控制服务、凭据保管组件及获准的连接组件。恶意管理员、已被完全控制的宿主、未知内核漏洞不在首版保证范围。第三方模型服务会收到被允许发送的上下文；“本地工作台”不意味着所有数据永不离机。

## 2. 六个必须独立验证的边界

| 边界 | 必须执行的限制 | 反例验证 |
|---|---|---|
| 文件 | 独立副本，不挂整机 HOME；路径归一化并拒绝越界链接 | `..`、符号链接、junction、硬链接、大小写/路径别名越界 |
| 进程 | 非特权、资源上限、完整进程树回收；不暴露运行时管理 socket | 创建后台子进程、访问宿主进程、特权请求 |
| 网络 | 默认拒绝直接出网及访问宿主/内网；仅允许受控服务入口 | 直连 IP、DNS、IPv6、重定向、内网及管理端口 |
| 凭据 | 上游密钥仅在沙箱外；最小有效期和作用域的入口身份 | 环境变量、配置、日志、进程参数、错误响应、成果包扫描 |
| 任务 | 权限按主体与任务绑定，派生不超权 | 猜任务 ID、读取兄弟成果、伪造父任务、递归派生 |
| 成果 | 快照导出与应用分别授权，不执行内容 | 路径穿越、链接覆盖、并发修改、恶意终端/HTML 内容 |

## 3. 凭据外置的实际含义

**用户不在 Agent 沙箱里填写上游 API Key 或密码，Agent 沙箱里也不出现这些真实凭据。** 用户可以在 Dock 的可信设置页输入，或连接已有可信服务。

沙箱内仍可能需要调用 Dock 的短期环境身份。它不是“无秘密”，而是只允许本环境代表本任务调用有限能力的身份：绑定 environment/task、允许的服务与动作、额度、期限、撤销代次，可撤销；请求还必须带防重放信息。优先使用每环境专用 IPC 通道或运行时句柄绑定；若平台只能提供短期令牌，必须绑定环境通道/进程上下文并限制重放，不能仅凭 task_id、loopback 来源或可猜测 header 认证。身份只在 Gateway 验证，不能写入普通日志或成果包。

### 模型路径

Agent → Dock 模型代理 → 已配置的 Magpie 或兼容模型服务。

Dock 将受限凭证换成已批准的上游认证，不接受 Agent 任意指定上游 URL、账户、认证头或模型。模型流式响应需保持可用，但上游头、错误和调试信息必须过滤。访问 Magpie 的模型接口不等于可访问其管理接口。

不支持外置凭据的认证方式应标注不兼容，而不是把登录数据库或浏览器 Cookie 搬进 Agent 环境。订阅登录、刷新令牌和 OAuth 授权需逐适配器验证。

### MCP 路径

按凭据需求和执行风险分三类：

1. **无凭据、本地运算 MCP**：可放在 Agent 沙箱内，但遵守同样的文件与网络边界。
2. **远端 MCP**：Dock 代理处理认证、工具授权与连接生命周期；不向 Agent 转发上游认证信息。
3. **需要本地进程及真实凭据的 MCP**：在独立受控连接环境运行，仅授必要凭据、目录和网络；禁止把任意第三方 MCP 直接作为宿主高权限进程运行。不能提供受控连接环境时，该类先不支持。

第三类服务进程会接触自身必需凭据，因此“不进入 Agent 沙箱”不等于“任何执行环境都不接触凭据”。它必须由架构中的 `Connector Environment Manager` 创建为独立连接环境：绑定单一 MCP 服务、独立进程树、最小网络出口、独立生命周期和可撤销的 `CredentialBinding`；Controller 停止任务时同时回收连接环境。不能退化为宿主高权限常驻进程，不能把同一连接环境共享给无关任务。连接环境也是风险面，必须按服务分离授权，不能共享全部钥匙。

代理必须覆盖需要的协议方法，而不只是 `tools/call`：工具发现、资源读取、提示模板、通知、取消等按支持范围显式开放；服务发起的额外请求默认拒绝，兼容性未确认前不转发任意反向能力。

### Agent 间的消息与成果

消息正文可以落在受保护存储中，平台记录引用、摘要和哈希。来自子 Agent 的消息是低信任输入，不能改变策略优先级。

成果交接不是默认复制目录。发布成果时必须记录快照摘要、来源环境、文件清单、敏感性标签和允许传播范围。跨环境读取先检查：接收任务关系、文件/字段标签、是否允许送入模型或 MCP、是否需要用户确认；高敏感文件默认拒绝或要求用户选择脱敏版本。即使接收 Agent 已获 `artifact.read`，也不能自动把成果转发到它可用的所有外部能力。

## 4. 有凭据代理仍然可能造成损失

持有令牌的 Agent 即使看不到原始密钥，也可能消费额度、修改远端数据或通过已授权请求外传项目内容。因此授权不是一个“允许联网”开关。

- 模型：限制模型、请求尺寸、并发、令牌上限、请求频率和任务累计预算；没有可靠计价时显示未知，使用调用次数/令牌/时长硬上限，不声称精准费用封顶。
- MCP：限制服务、工具、参数对象与只读/写入动作；工具名称或描述自称只读不能作为安全依据。
- 任意 URL、SQL、shell 或上传类工具：普通工具级白名单不足以约束目的地与数据，首版拒绝或逐次批准具体操作，不提供无限通行模板。
- 模型与获准工具本身也是数据出口；用户必须理解选定项目内容可能进入这些服务。不能声称“允许模型调用但保证源码不离机”。

## 5. 权限派生与审批

子任务有效权限 = 父任务可委派权限 ∩ 模板允许权限 ∩ 用户批准权限 ∩ 当前系统策略。

Dock 先检查身份、隔离边界、权限上限与额度，再根据用户选择的审批模式处理允许范围内的请求：安全模式逐次询问，标准模式按风险询问，自动授权模式自动批准。系统禁止项始终拒绝。模式由可信 UI 设置，Agent 和 Skill 均不得切换模式。自动授权记录必须标记为“用户所选策略自动批准”，不能伪装成人工点击。

子任务请求超出已有可委派权限时，必须通过可信 UI 扩大授权范围；消息里写“用户已批准”无效。子任务不能比父任务采用更宽松的审批模式，除非用户另行设置。父任务撤权时子任务同步失效。到期或停止后在 Gateway 每次请求处检查，不只在启动时检查一次。切换到更严格模式后，尚未执行的请求按新模式重新判断，已发出的外部动作不假装可撤回。

创建请求用幂等键绑定调用者、父任务和请求内容；重复请求返回同一结果，参数变化返回冲突。并发额度应在创建前原子预留，创建失败回收，防止并发派生超额。重启核对活动环境后再释放额度，不能将孤儿环境当不存在。

审批也有幂等标识、参数摘要、目标版本和期限。批准后参数发生变化必须重新申请。非幂等外部写入超时后状态为“结果未知”，不得自动重试造成重复发送或重复修改。

## 6. 本地控制面与界面

- 管理服务优先使用有访问控制的本地 IPC；若采用 loopback HTTP，仍需认证、Origin/CSRF 防护、请求校验和生命周期管理。
- Agent 的能力端点与管理端点分离，不接受 Agent 提供的任意宿主路径或运行参数。
- 不将 Controller 直接暴露到局域网。沙箱需要的入口使用专门绑定与最小路由，不用开放整台宿主网络解决连接问题。
- Agent 的 Web UI 与 Dock 可信审批页隔离来源和权限，不能共享管理 Cookie 或桌面原生桥。
- 终端控制序列、自动打开链接、剪贴板和文件下载有独立处理规则；渲染内容不能触发原生 API。
- 桌面 UI 关闭、Controller 崩溃或策略服务不可用时，禁止新调用；凭证短期失效，运行时监督机制回收孤儿进程。具体回收机制须通过断进程测试确认。

## 7. 项目导入和成果应用

默认使用独立复制快照。只读项目挂载或 Git worktree 可以后续优化，但不可假设 worktree 天然不共享敏感 Git 元数据或宿主路径。

导入时保留文件清单、摘要和权限；不导入链接目标之外的文件，不把包含密钥的全局配置纳入副本。扫描是辅助措施，不能保证识别所有秘密。

应用时重新核对源基线，拒绝路径逃逸、异常链接、非预期设备文件和目标版本变化。分阶段写入，保留回退数据；若不能实现全量原子应用，明确显示部分失败和已写入清单，提供恢复入口。不要笼统承诺所有文件与外部操作都能一键回滚。

## 8. 兼容矩阵必须用测试填充

以下全部是目标/待验证，不是已支持：

| 目标 | 检查维度 | 当前状态 |
|---|---|---|
| Codex | 固定版本、独立配置、模型代理、MCP、停止、事件/恢复 | 待验证 |
| Claude Code | 同上；认证及模型接入差异 | 待验证 |
| DeepSeek Harness | 同上；若有 Web UI 则增加来源隔离与端口限制 | 待验证 |
| Magpie | 模型入口、配置获取、管理隔离、版本兼容、不改全局状态 | 待验证 |
| Skill（纯指令与引用资料） | 各 Harness 的发现/加载路径、触发与显式调用、相对引用、禁用和版本固定 | 待验证 |
| Skill（含脚本或依赖） | 沙箱内执行、依赖与路径兼容、MCP 调用、网络/文件越界拒绝、停止回收 | 待验证 |
| 无凭据 stdio MCP | 生命周期、工具发现/调用、取消与文件限制 | 待验证 |
| 带凭据 stdio MCP | 独立连接环境、凭据保管、最小权限 | 待验证 |
| 远端 HTTP MCP | 协议协商、认证、流式会话、取消、撤权 | 待验证 |
| 其他/旧传输与 OAuth | 按赛题主流范围补齐并逐版本测试 | 待确认范围、待验证 |

每条最终记录必须包含：版本、操作系统、认证方式、运行时、测试日期、通过/受限/不支持、证据路径。外部工具文档声明的支持范围不能直接复制成 Dock 的兼容名单。

### Skill 的接入与测试

Skill 不是只读说明就天然可信：它可能包含脚本、依赖、文件路径和外部工具调用。通过用户选择的包生成沙箱专用副本，不整份挂载宿主技能库；检查符号链接与引用路径，不携带本机凭据或未授权私人资料。

每个适配 Harness 至少测试：①发现并加载一个纯指令 Skill；②读取相对路径引用；③执行一个合成脚本；④通过受控 MCP 完成一次调用；⑤恶意 Skill 读取宿主文件、外传测试数据、索取密钥或切换审批模式时被拒。结果记录 Skill 版本/摘要、Harness 版本、所需依赖及运行证据，不能只证明文件已复制。

Skill 可以要求能力，但不能自行获得授权。自动授权模式也不放宽其文件、网络和凭据边界。任务中固定 Skill 版本，更新后重新检查依赖与权限；不假定同一个 Skill 在所有 Harness 中都有相同触发行为。

## 9. 更新与日志

Agent、模板、Magpie 和 Dock 分别记录版本。任务中不自动切换依赖版本。已有 Magpie 由用户自行维护；新版本通过探测也只代表探测项可用，未覆盖项仍未知。关键安全接口失败时停用，不降级安全。

安装包、依赖和模板需固定来源与版本，记录许可证与校验信息。配套安装/更新必须得到用户同意，不替换用户自行管理的实例。

日志默认记录生命周期、拒绝原因和目标摘要；完整提示词和工具输出按敏感数据处理，导出前预览并脱敏。验证凭据泄漏使用合成测试密钥，禁止把真实密钥写入测试报告。保留策略既要支持诊断，也要允许用户删除记录与成果。
